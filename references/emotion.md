# 情感控制

四种情感模式、八维情感向量与 bias 归一化。只想快速用一下时看 `SKILL.md` 的「情感控制」；要精确调向量或解释结果时读这份。

## 模式总览

不传任何情感参数时是**模式 0**：直接用音色参考音频自带的情感。

| 模式 | 触发 | `--emo-alpha` 默认 | 传给上游的实际参数 |
|---|---|---|---|
| 0 音色即情感 | 默认 | 忽略 | 情感参数全留空 |
| 1 情感参考音频 | `--emo-audio <音色/路径>` | 0.65 | `emo_audio_prompt` + `emo_alpha` |
| 2 八维向量 | `--emo-vec <向量>` | 1.0 | `emo_vector`（先做 bias 归一化）+ `use_random` |
| 3 情感描述文本 | `--emo-text "<描述>"` | 0.6 | `use_emo_text=True` + `emo_text` |

模式可以自动推断，也可以用 `--emo-mode 0|1|2|3` 显式指定。**显式指定的模式与传入的情感参数冲突时会直接报错，不会静默丢弃**——静默丢弃对智能体是最坏的行为。

模式 3 会多跑一次情感分类模型，约多花 30% 时间；想省时间可以配 `--fast`（beam 从 3 降到 1，速度约快 3 倍，代价是韵律随机性下降）。

## 八维情感向量

顺序固定（与上游 `infer_v2.py` 的 `desired_vector_order` 一致，不能改）：

| # | 1 | 2 | 3 | 4 | 5 | 6 | 7 | 8 |
|---|---|---|---|---|---|---|---|---|
| 中文 | 喜 | 怒 | 哀 | 惧 | 厌恶 | 低落 | 惊喜 | 平静 |
| English | happy | angry | sad | afraid | disgusted | melancholic | surprised | calm |

两种写法都支持：

```bash
--emo-vec 0,0,0.8,0,0,0,0,0      # 位置写法，必须正好 8 个数
--emo-vec 哀=0.8                  # 命名写法，未提及的分量记 0
--emo-vec 哀=0.6,喜=0.2           # 命名写法可以多段
```

JSON API 还接受 8 元数组和 `{"哀": 0.8, "平静": 0.2}` 对象，见 `references/rest-api.md`。

## bias 归一化（实现细节，但会影响结果）

上游的 `infer()` **不会**自动调用 `normalize_emo_vec()`——webui 是自己调完再传进去的。本 CLI 补上了这一步，所以模式 2 的实际向量是：

1. 每个分量乘上 bias `[0.9375, 0.875, 1.0, 1.0, 0.9375, 0.9375, 0.6875, 0.5625]`
2. 若总和超过 0.8，按比例缩放到总和 0.8
3. 再乘 `emo_alpha`（默认 1.0）

例：`喜=0.5,惊喜=0.5` → 0.46875 / 0.34375（总和 0.8125 超标）→ **0.4615 / 0.3385**。结果里的 `params.emo_vector` 回显的就是最终值。
